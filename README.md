# Vision Motion

**Предварительная проверка зрения, которой управляют только жестами руки перед обычной веб-камерой. Без клавиатуры, мыши и тачпада.**

ADMIT HACKATHON 2026 · кейс «MOTION: Камера вместо джойстика» · направление: **свободный вариант**.

| | |
|---|---|
| **Живой сайт** | https://yerassyl-eco.github.io/VisionMotion/ — откройте в Chrome, разрешите камеру, покажите 👍 |
| **Без камеры (демо)** | https://yerassyl-eco.github.io/VisionMotion/?demo — жесты подаются с панели и клавишами |

> Видео с камеры обрабатывается только в браузере и никуда не отправляется.
> Vision Motion — предварительный скрининг, **не медицинский диагноз**. При проблемах со зрением обратитесь к офтальмологу.

## 1. Что это и зачем

Человек садится перед ноутбуком, открывает ссылку и проходит пять визуальных тестов: остроту зрения, радиальную фигуру, дуохром, сетку Амслера и цветовое зрение. Отвечает он **только руками**: показывает направление пальцем, подтверждает кулаком, листает результаты знаком «ОК». Поэтому тест может пройти даже человек, который не умеет пользоваться мышью, и никто не трогает общую клавиатуру.

Законченный сценарий:

```
Главный экран ─👍→ проверка камеры ─👍→ анкета (1–4 пальца + ✊) ─→ подготовка ─👍→
  5 тестов: инструкция ─👍→ ответы 👈👉☝️👇 → ✊ подтвердить → «Готовы к следующему тесту?» 👍
─→ «Скрининг завершён. Хотите увидеть результаты?» 👍
─→ результат каждого теста (👌 дальше, 👈 назад) ─👌→ карта зрения ─👌→ итог (👍 пройти заново)
```

Движение → распознавание → действие → результат: каждый жест сразу меняет экран, а в конце человек получает отчёт по пяти тестам с советами.

**Интерфейс под жесты.** Каждый экран целиком помещается в окно браузера (проверено на 1280×720, 1440×800, 1512×860), прокручивать ничего не нужно. Нужный жест всегда нарисован крупно рядом с содержимым: «Покажите кулак — чтобы подтвердить ответ», «Покажите палец вверх — чтобы продолжить». Варианты ответа — большие карточки с рукой и стрелкой направления. Внизу всегда одна строка «что сделать сейчас».

## 3. Как запустить

**Проще всего — открыть живой сайт:** https://yerassyl-eco.github.io/VisionMotion/

Локально нужен Node.js 20+ и современный Chrome, Edge или Safari:

```bash
git clone https://github.com/Yerassyl-eco/VisionMotion.git
cd VisionMotion
npm install        # также копирует MediaPipe WASM в public/ (модели уже лежат в public/models)
npm run dev        # http://localhost:5173
```

Production-сборка и тесты:

```bash
npm run build && npm run preview   # http://localhost:4173
npm test                           # 29 автотестов
```

- Камера в браузере работает только на `localhost` или по `https://`.
- Если камеры нет или хочется пройти сценарий быстро — `?demo`: появится панель жестов; клавиши ← → ↑ ↓ = указание, Enter = ✊, T = 👍, P = ✋, O = 👌, 1–4 = число пальцев.
- `?debug` показывает диагностику камеры и модели (статус, кадры, FPS, делегат GPU/CPU).
- Если браузер не запускает видео без клика (Safari, энергосбережение), сайт показывает кнопку «Включить камеру» и сам перезапускает остановившееся видео.

## 4. Жесты и собственная логика распознавания

MediaPipe даёт только 21 точку руки. **Какой это жест — решает наш собственный rule-based движок** (`src/vision/gestureEngine/`); готовый GestureRecognizer из MediaPipe не используется.

| Жест | Действие | Как распознаётся |
|---|---|---|
| 👍 палец вверх | начать, продолжить, следующий тест, пройти заново | 4 пальца согнуты, большой вытянут, направлен вверх и выше костяшек |
| ✊ кулак | подтвердить ответ | все пальцы согнуты, большой прижат |
| 👈 👉 ☝️ 👇 указание | выбрать ответ / направление, 👈 — назад | вытянут только указательный; направление — по вектору от основания пальца к кончику, проверяется близость к оси |
| ✋ ладонь | отменить выбор, повторить инструкцию | все пальцы и большой отставлены |
| 👌 «ОК» | следующий результат, карта, итог | кончики большого и указательного сомкнуты, остальные три вытянуты |
| ✌️ / 3 / 4 пальца | ответ 2 / 3 / 4 в анкете | поднятые пальцы считаются по порядку; «четыре» отличается от ладони тем, что кончик большого пальца лежит на ладони (≈0.4 размера ладони против ≈0.9+) |

**Геометрия** (`geometry.ts`, `classifyHand.ts`). Точки переводятся в «пространство пользователя» (зеркало, поправка на соотношение сторон). Для каждого пальца считаются *reach* (во сколько раз кончик дальше от запястья, чем средний сустав) и *straightness* (косинус между фалангами); через `smoothstep` получается непрерывная «вытянутость» 0…1, устойчивая к повороту руки. Confidence складывается из запаса по каждому правилу.

**Время** (`GestureEngine.ts`). Голосование в окне 320 мс (жест ≥ 60% окна при confidence ≥ 0.55) → удержание 450–700 мс в зависимости от жеста → latch (тот же жест не срабатывает повторно, пока руку не «отпустили») → cooldown 650 мс. Ответ **никогда** не записывается одним жестом: сначала выбор, затем ✊.

**Тесты на реальных данных.** Классификатор проверяется на реальных точках MediaPipe, извлечённых из фотографий рук (👍, ✊, ☝️, 👈, ✌️, ✋, 1–5 пальцев); повороты тех же точек проверяют все четыре направления указания.

## 5. Режим «ошибка»

Вместо «жест не распознан» движок на каждом кадре ищет конкретную проблему, выбирает самую важную и показывает её в панели камеры (полоса **СИГНАЛ**), а на главном экране — под кнопкой старта. Чтобы подсказки не мигали, проблема должна продержаться 350 мс, прежде чем появится, и держится на экране не меньше 1.1 с. Каждая подсказка отвечает на два вопроса: что система видит и что сделать.

| Ситуация | Как определяется | Что видит пользователь (заголовок · как исправить) |
|---|---|---|
| Руки нет в кадре | нет руки дольше 700 мс | «Я пока не вижу вашу руку» · «Покажите ладонь в камеру на уровне груди, на расстоянии вытянутой руки» |
| Рука выходит за край | точки у края кадра; сторона — с учётом зеркала | «Рука частично выходит за левый край кадра» · «Сдвиньте руку немного вправо, чтобы в кадре была вся ладонь» (так же для правого, верхнего и нижнего края) |
| Слишком далеко / близко | размер ладони < 11% или > 45% высоты кадра | «Рука слишком далеко» · «Поднесите руку ближе к камере — ладонь должна быть крупнее» / «Рука слишком близко к камере» · «Отодвиньте руку немного назад» |
| Две руки | в кадре больше одной руки | «В кадре две руки» · «Оставьте в кадре только одну руку — вторую опустите» |
| Рука двигается | скорость запястья > 3.2 размера ладони/с | «Рука двигается слишком быстро» · «Держите руку неподвижно около секунды» |
| Жест показан на мгновение | жест пропал, пройдя 25–99% удержания | «Жест показан слишком быстро» · «Задержите жест на секунду, пока линия под ним не заполнится» |
| Палец по диагонали | направление отклонено от оси | «Направление пальца неоднозначное (по диагонали)» · «Покажите направление чётче — строго вверх, вниз, влево или вправо» |
| Лишние пальцы при указании | вытянут не только указательный | «Вытянуто несколько пальцев» · «Для направления оставьте вытянутым только указательный палец, остальные согните» |
| Большой палец не вверх | 👍 почти показан | «Большой палец смотрит в сторону» · «Направьте большой палец строго вверх, остальные пальцы сожмите» |
| Кулак не сжат | пальцы полусогнуты | «Пальцы согнуты не до конца» · «Сожмите кулак плотнее — или, наоборот, выпрямите нужный палец полностью» |
| Палец смотрит в камеру | указательный сильно укорочен в кадре | «Палец направлен прямо в камеру» · «Поверните руку боком: указательный палец должен смотреть вверх, вниз, влево или вправо» |
| Плохо видно пальцы | низкая уверенность модели или правила | «Я плохо различаю пальцы» · «Поверните ладонь к камере и проверьте, что рука хорошо освещена» |
| Положение лица | FaceDetector: нет лица, лицо низко / у края, слишком близко / далеко | «Камера не видит ваше лицо» · «Сядьте так, чтобы лицо полностью оказалось в кадре»; «Вы слишком близко к экрану» · «Отодвиньтесь немного назад. Рекомендуемое расстояние — около 50–70 см» |
| Жест не к месту | state machine отклоняет жест в текущей фазе | например ✊ до выбора ответа: «Сначала выберите ответ указательным пальцем (влево — …, вправо — …), затем подтвердите кулаком» |
| Проблемы с камерой | коды ошибок `getUserMedia` | «Для прохождения тестов необходим доступ к камере» · «Нажмите на значок камеры в адресной строке и выберите «Разрешить». На Mac также проверьте: Системные настройки → Конфиденциальность и безопасность → Камера» + кнопка «Разрешить камеру» |

Проверить вручную: уберите руку, выведите ладонь за край кадра, поднесите её вплотную, покажите палец по диагонали, покажите 👍 на полсекунды, покажите ✊ до выбора ответа.

## 7. Бонусы

- **Собственная логика распознавания** — rule-based классификатор 11 жестов, временной движок и Error Mode написаны командой, покрыты тестами на реальных точках MediaPipe.
- **Прогресс пользователя** — результаты сохраняются в `localStorage`, на главном экране показывается последний скрининг.
- **Телефон** — адаптивная раскладка и фронтальная камера (`facingMode: user`); основной сценарий рассчитан на ноутбук.
- **Звук и визуальные эффекты** — короткие звуки на распознавание, подтверждение и ошибку (Web Audio, выключаются кнопкой «Звук»); процедурно нарисованная радужка на главном экране, которая «замечает» руку (зрачок сужается, прицел сходится, кольцо заполняется при удержании 👍); анимированные карточки и диаграммы.
- **Надёжность камеры** — автоматический перезапуск остановившегося видео, понятные ошибки доступа, режим `?debug`.

## 8. Архитектура

```
src/
  App.tsx                   — каркас экрана, маршрутизация жестов, эффекты
  state/
    testMachine.ts          — state machine (reducer) и routeGesture: жест → действие или подсказка
    phaseActions.ts         — что показывать «сейчас» для каждой фазы
  vision/
    VisionRuntime.ts        — камера, модели, цикл кадров вне React, восстановление видео
    camera/camera.ts        — getUserMedia и понятные ошибки
    handTracking/           — загрузка MediaPipe (локально → CDN), отрисовка скелета
    gestureEngine/          — геометрия, классификатор, временной движок, тексты Error Mode, тесты
  tests/                    — 5 визуальных тестов: стимулы, варианты ответа, интерпретация
  pages/                    — главный экран, калибровка, анкета, инструкции, тест, «готовы?», результаты, карта, итог
  components/               — камера-инструмент, крупные подсказки жестов, карточки ответов, радужка и др.
  data/                     — анкета, советы, темы тестов
  utils/                    — localStorage, звуки
public/models/              — hand_landmarker.task, blaze_face_short_range.tflite
public/hands/               — фото рук 1–4 для анкеты
.github/workflows/deploy.yml — тесты, сборка и деплой на GitHub Pages при каждом пуше в main
```

- **State machine** с явными фазами: `LANDING → CAMERA_SETUP → PROFILE → PREPARATION → TEST_INTRO → TEST_ACTIVE → ANSWER_SELECTED → ANSWER_CONFIRMED → TEST_RESULT → … → COMPLETE → DETAILS → VISION_MAP → FINAL_RESULT`. Кнопки (запасной ввод), dev-панель и камера идут через один `routeGesture`, поэтому поведение одинаковое.
- **Производительность:** инференс только на новых видеокадрах, лицо — на каждом 5-м; скелет рисуется в canvas без React; React получает снимок состояния ~11 раз в секунду.
- **Автотесты (29):** классификатор на реальных точках MediaPipe, временной движок, полный проход state machine только жестами, отсутствие диагностических формулировок.

## 10. Ограничения

- Это предварительный скрининг, **не диагноз**: приложение не пишет «у вас …», только «результат отличается от ожидаемого» и «обратитесь к офтальмологу при жалобах». Это проверяется автотестом.
- Размер символов зависит от экрана, расстояние контролируется приблизительно, поэтому острота выражается в уровнях теста, а не в клинических единицах. Цветовые тесты зависят от цветопередачи дисплея.
- На телефоне длинные экраны (тест, результаты) могут прокручиваться; на ноутбуке всё помещается в один экран.

## 11. Приватность

Видео обрабатывается локально и не сохраняется. В `localStorage` лежат только итоги тестов; ответы анкеты живут только до закрытия страницы, имя не спрашивается.
